# 本机摄像头与卡顿验证

在 Windows 项目根目录执行下面的命令。视频仍使用 HTTP/TCP MJPEG；
本机服务使用真实摄像头，机械臂强制为 DryRunArm，不需要 Jetson 或 Arm_Lib。

## 启动

先在旧服务、旧客户端所在终端按 `Ctrl+C` 关闭它们，再同步环境。Windows 运行中的进程会锁住
OpenCV 和服务启动文件；此时不要执行依赖卸载或重装。
当前环境已具备依赖时，可以直接使用 `uv run --no-sync` 替代下面的 `uv run --package ... --extra ...`。

```powershell
Set-Location E:\codes\test\gesture-recognition
uv sync --package gesture-client --extra local-server
uv run --package gesture-client --extra local-server python scripts/local_server.py --camera 0 --fps 15
```

另开终端：

```powershell
Set-Location E:\codes\test\gesture-recognition
uv run --package gesture-client --extra local-server gesture-client
```

界面填写地址 `127.0.0.1`、端口 `8896`，点击“连接并开始”。摄像头被占用时，
先关闭使用它的会议软件或旧服务。只有一个程序采集摄像头；客户端通过 HTTP 获取图片。
没有摄像头时把服务命令中的 `--camera 0` 改成 `--mock-camera`，画面中会出现移动圆点和帧编号。

## 改进后的处理方式

- 模型在后台加载、预热，与连接视频并行；停止再启动复用模型。权重变更或模型参数变更会重新加载。
- 摄像头只有一份最新 JPEG 缓存，每个 HTTP 客户端有独立帧序号，只发送新帧，不重播缓存帧。
- HTTP multipart 按 boundary、分部头部、Content-Length 解析；支持分块、合并读取，限制缓存大小。
- 接收线程只更新最新图像；界面定时读取，不通过逐帧 Qt 信号堆积图片。
- 推理按独立频率抽取最新帧，不等待控制接口；控制线程单独查询状态、发送动作，最多保留一个待发送动作。
- 超时的输入和动作不再使用；检测框只短暂叠加，避免旧结果长期覆盖新画面。
- Windows 数字摄像头优先 DirectShow，Linux USB 摄像头优先 V4L2；驱动不支持时自动回退。

画面 FPS 由采集和网络决定，不随推理 FPS 降低。默认显示上限 30 FPS、推理上限 10 FPS，
并不代表摄像头实际能达到这些帧率。CPU 线程和推理尺寸可在界面调整，需停止后重新启动生效。
稳定帧数仍按“完成的推理帧”计数，降低推理 FPS 会增加手势触发等待时间。

性能栏显示接收、显示、推理 FPS、带宽、解码和推理耗时、连接和模型加载耗时。
“接收后帧龄”从本机解码结束开始计算，不是 Jetson 到屏幕的总延迟。
不要将不同机器未同步的时间戳直接相减作为端到端延迟。

## 自动验证

验证会临时启动独立本机端口，运行真实模型和 Qt 图像转换、缩放，自动停止再启动验证缓存，
并发送一个模拟动作。不会覆盖 `client-settings.json` 或保存摄像头图片。
运行前关闭手动启动的摄像头服务。

```powershell
# 真实摄像头 + 真实 YOLO + 实际 Qt 绘图
uv run --package gesture-client --extra local-server python scripts/verify_local_stream.py --camera 0 --seconds 12

# 人为增加每次推理 350 ms，检查视频是否仍连续刷新
uv run --package gesture-client --extra local-server python scripts/verify_local_stream.py --camera 0 --seconds 12 --slow-inference 0.35

# 无摄像头也可验证相同链路
uv run --package gesture-client --extra local-server python scripts/verify_local_stream.py --mock-camera --seconds 12

# 协议、重复发帧、慢模型、慢接口、重连等回归测试
uv run --package gesture-client --extra local-server --group dev pytest
```

JSON 输出给出首帧等待、稳定显示帧率、推理帧率、显示间隔、缓存复用和模拟动作结果。
验证默认使用 Qt 离屏模式，在真实 Qt 控件中绘制，不会弹出窗口。
回环网络验证只能证明程序链路正常；Jetson Wi-Fi、供电、硬件编码与驱动问题需要硬件现场复测。

YOLOv5 的两个推理 autocast 调用已适配项目固定的 PyTorch 2.5 API，避免每次推理打印弃用警告。
如果旧环境同时装过 `opencv-python` 和 `opencv-python-headless`，同步删除 headless 后可能影响
两者共用的 `cv2` 文件；可执行一次
`uv sync --package gesture-client --extra local-server --reinstall-package opencv-python` 修复。

## 2026-10-09 本机验证结果

Windows 摄像头 0、640×480、目标 15 FPS、PyTorch 2.5.1 CPU、真实模型 `models/best.pt`。
使用真实回环 HTTP 和 Qt 离屏绘制；没有保存摄像头图片。

| 场景 | 首次画面 | 模型加载与预热 | 稳定显示 FPS | 推理耗时 |
|---|---:|---:|---:|---:|
| 正常推理 | 0.750 s | 5.656 s | 14.97 | 75.4 ms |
| 每次推理额外延迟 350 ms | 0.672 s | 5.500 s | 14.18 | 433.8 ms |

两次均验证停止后重新启动复用模型缓存、实际 Qt 图像绘制、模拟动作执行、线程正常退出。
测试脚本会自动关闭自己的服务，不会终止已存在的手动服务。
23 项回归测试通过，涵盖 multipart 分块/合并/长度异常、独立订阅者不重复发帧、
慢模型和慢 HTTP 下的视频独立刷新、重连、过期动作丢弃、模型失败保留预览等。
服务端和共享模块通过 Python 3.6 语法检查，未进行真实 Jetson 硬件复测。
